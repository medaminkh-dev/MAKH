# selfhost — MAKH rebuilds its own userland on MAKH (F21-d)

The self-hosting summit. The earlier F21 bricks put a compiler (tcc, 21-A), a C
library (musl sysroot, 21-B) and a build system (make, 21-C) on MAKH. This one
closes the loop: MAKH uses that toolchain to **rebuild a program it ships**.

`/bin/muslhello` is MAKH's first real-libc program (`user/musl/hello.c`): it
exercises the whole libc ABI end to end — crt startup, TLS via `%fs`
(`__thread`), the heap, buffered stdio, argv/auxv — and exits **42** iff every
part worked. The shipped binary was cross-built on a host with zig cc (a
static-PIE).

`Makefile` here rebuilds that same source with the **on-MAKH** toolchain
(`tcc` + the `/usr` musl sysroot), driven by `make`, into a static non-PIE
executable. `kernel/tests/test_f21.c` runs the shipped `/bin/muslhello`
(baseline, exit 42), then `make -C /share/selfhost`, then the freshly built
`/share/selfhost/muslhello` — and asserts it also exits 42 with the same output.
A program MAKH ships, regenerated by MAKH, behaving identically.

`muslhello.c` is not checked in here: the `$(INITRD)` recipe copies MAKH's own
`user/musl/hello.c` into `/share/selfhost/muslhello.c`, so the thing rebuilt is
literally MAKH's shipped source, with no second copy to drift.

## Next (beyond this summit)

The further reach is tcc compiling tcc on MAKH — a compiler rebuilding itself.
That needs the full tinycc source tree staged and is a heavier lift; this brick
proves the toolchain and the ABI are sound enough to regenerate real MAKH
userland first.
