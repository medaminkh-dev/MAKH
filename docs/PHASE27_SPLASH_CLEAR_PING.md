## 1. Boot splash + clean handoff (FB-2)

On a quiet interactive boot the framebuffer console is held back while the kernel
finishes init, and instead the splash is shown:

- **`fb_splash_show()`** paints the dark field, the centred **fennec logo**
  (an 8-bit alpha mask in `kernel/include/fb_logo.h`, generated by
  `tools/genlogo.py` and drawn in cream over the charcoal background), a
  **"starting MAKH"** caption, and the first spinner frame.
- **`fb_splash_tick(frame)`** redraws a **mellow spinning loader** — 12 dots on a
  circle with a fading tail, rotated by a fixed `cos/sin*1000` table (integer
  only; the kernel has no FPU/SSE).
- Just before the shell starts (timer up), the loader spins for ~1.8 s, then the
  screen is **cleared** and the terminal starts at the top. This gives the clear
  *boot → terminal* separation the old flow lacked (the boot log used to scroll
  straight into the prompt). Boot logs still go to the serial mirror throughout.

The splash is shown only on a normal boot: `makh.test` (headless) and
`makh.verbose` (wants the log) skip it, and a boot with no usable framebuffer
falls back to plain text.

## 2. `clear` + ANSI escapes

A small ANSI/VT handler in the terminal layer (`kernel/vga.c`) drives the
existing `terminal_clear` / `setcursor` / `setcolor`, so both the framebuffer
console and the VGA-text fallback understand:

- **CSI J** — erase display (clear screen),
- **CSI H / f** — cursor position,
- **CSI m (SGR)** — colours: `0` reset, `1` bold/bright, `30–37`/`90–97`
  foreground, `40–47`/`100–107` background, mapped onto the 16-colour palette.

Native **`/bin/clear`** (`user/clear.c`) writes `ESC[2J ESC[H`. Programs that emit
colour now render in colour on the pixel console.

## 3. Richer `ping`

The kernel shell's `ping` (reachable with `makh.kshell`) now prints the reply
TTL and a proper statistics block:

```
PING 10.0.2.2: 3 echo requests, 56 data bytes
64 bytes from 10.0.2.2: icmp_seq=1 ttl=255 time=20 ms
64 bytes from 10.0.2.2: icmp_seq=2 ttl=255 time=0 ms
...
--- 10.0.2.2 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss
rtt min/avg/max = 0/6/20 ms
```

TTL is plumbed from the IP header through `ipv4_input → icmp_input` into the ping
slot and out of `icmp_ping(..., uint8_t *ttl_out)`; the shell accumulates
min/avg/max and spaces packets ~0.5 s apart. (RTT is still whole-milliseconds —
the clock is ms-resolution, which on QEMU's fast slirp link reads 0 or the
occasional 5–20; a microsecond clock is a later refinement.)

## 5. Not in this brick (next)

- **`wget`** and a user-space `ping`: both need sockets exposed to ring 3
  (a `socket`/`connect`/`send`/`recv` syscall layer); that is its own brick.
- Microsecond RTT resolution (a `clock_now_us`), and a fuller VGA replacement.
